# 中断后的 Agent 复用策略：方案 A 已确认

日期：2026-09-08。状态：用户已确认方案 A，实施见 [会话池计划](2026-09-08-session-pool-plan.md)。方案 B 未选择。

## 需要决策的边界

用户要求每个视频复用原主会话和子成员，失败时不静默创建替代者。CLI 2.1.261 的真实合成验证表明，预算中断可能把原生子成员置为拒绝 SendMessage 恢复的取消状态。正常完成成员的恢复能力不能外推到这个状态；保存了ID和transcript也不能保证CLI允许自动恢复。

官方 [子 Agent 恢复说明](https://code.claude.com/docs/en/sub-agents#resume-subagents) 区分正常完成/TaskStop与用户或SDK停止：后者拒绝代理消息，需要在可用的交互式子成员面板中由用户恢复。当前服务端headless流程不能依赖该交互入口。不得编辑厂商停止标记、伪造完成事件或把新实例说成原成员。

## 方案 A：独立 CLI 会话池（推荐讨论）

保留主协调会话；每个逻辑子成员使用独立的 Claude CLI 普通会话UUID，由本地程序投递任务和汇总结果。每个worker通过 claude -p --resume <worker_session_id>继续，程序明确登记主/worker关系。这是应用层管理的子成员，不冒充原生Agent工具实例。

保留已实现的固定输入、八方向规则、标签/证据校验、结果回执和最终UID JSON。新增普通会话执行证明适配器，取消主模型原样复述整份任务包再调用原生Agent的成本。预算中断、配置重新加载、完整历史备份仍需真实验收；不能预先承诺永久恢复。

迁移显式建立旧原生成员与新worker UUID的关系，旧原始证据和失败记录保留。未获同意不启动新worker。官方 [普通会话管理](https://code.claude.com/docs/en/sessions) 支持按UUID恢复print/SDK会话；本次主会话也已跨进程恢复，本阶段worker池的单任务分析到画像文件流程已实现并完成真实CLI合成验证，自动批量协调仍待后续接入。

## 方案 B：继续原生子 Agent，显式替换不可恢复成员

保留当前执行适配器与可恢复成员；把拒绝恢复的成员标为不可用，经用户明确授权后创建新的同角色成员并保留旧新ID映射。不能满足所有异常后始终保留同一实际agent_id的绝对要求。新成员需要完整原生创建/握手证据；不得只修改登记文件。CLI预算停止仍可能再次导致取消，因此预算和中断策略需要持续验收。

## 保持现状

未选择方案前停止新成员创建和付费调用；可查询、审阅和备份已有记录。停止成员的原ID不会被覆盖。独立整楼氛围报告、网页、自动批量分析与生产部署不随本决策自动扩展。

## 后续验收

确认一种方案后制定该方案的实现计划：持久ID映射、不中断有效成员、配置/规则重新加载、同ID跨进程恢复、失败/取消与费用记录、输入到最终文件的合成闭环及受限真实验证。沿用原输入/输出协议，任何变化明确版本化。既定真实调用总预算不自动重置。
