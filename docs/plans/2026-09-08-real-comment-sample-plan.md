# 真实评论小样本画像验证

日期：2026-09-08。用户确认先产出可读的真实评论画像，再推进批量调度；已有授权使用本地 Claude CLI，费用以完成目标并尽量节约为准。

## 范围与规则

使用用户指定的本地视频导出，选择少量文本信息较充分的用户，保留这些用户在已采集批次中的全部评论及本地可获得的关联楼层内容。源数据只读，抽样派生批次使用新的 export_id，保留原始 UID、评论 ID、正文和回复关系，在 Git 忽略目录保存原批次引用、抽样清单与覆盖限制。不得把小样本完成标为整视频分析完成。

采用已确认的讨论分析标准 0.1 中八个方向和现有候选取值；去掉合成测试强制 insufficient 的规则。论述依据的子项尚未固定为扁平标签，只作证据支持的文字观察，不临时创造标签。保留可判断/歧义/不足/不适用区别；不推断永久人格、真实心理或动机，不对未采集到的互动下结论。背景沿用原 README 并标注其来源未独立核验，不联网补充剧情事实。

## 执行与验收

- [x] 核对源数据、背景、目标用户的全部现有发言及上下文缺口，冻结小样本和正式运行提示文件。
- [x] 使用现有会话池与任务输入/输出协议，逐步执行用户初步、楼层、复核和综合任务；所有模型结果必须经过相同严格证据校验，不用手工修改输出绕过校验。
- [x] 审阅结论是否有对应评论原文、是否混淆剧情人物与真实用户、是否把假设当事实或把缺少回复当回避；结构校验通过不等于质量验收通过。
- [x] 保存 UID JSON 和中文可读版，展示具体观察、证据引用、重要例外和覆盖限制。分析输出、采集内容与验证脚本仅存本地忽略目录，不提交 Git。

本轮不实现新的批量调度或网页，不宣称样本具有统计代表性。若数据没有楼中楼，只验收现有主评论中的可观察表达，涉及互动的方向明确说明缺口。

## 扩大样本前需要澄清的边界

- 玩梗式短句不能仅凭褒贬词就确定立场，应明确何时保留歧义。
- 预测中的不确定性与立场上的部分/有条件认同应区分，避免把可能性措辞直接映射成条件立场。
- 对期待等表达的描述应限于文本线索，不将单个语气词扩展成强心理状态。
- 本轮产物保留模型原文与独立阅读提示；没有将机器校验通过等同于量表或画像质量已经验证。
