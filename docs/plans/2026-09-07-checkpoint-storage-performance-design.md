# 检查点与入库链路性能优化设计

状态：独立审阅问题已修订并通过复审，用户已确认；A、B实现、独立审阅及整体回归验收完成。分支：`opt/checkpoint-storage-performance`。

## 目标与阶段边界

减少请求计数更新中的大JSON读写，以及后台结果入库前的目录生成、复制和重复解析。保持相同输入下的评论集合、正文、UID/楼关系、覆盖状态、周期证明及导出内容一致。

本功能分A检查点、B后台直接入库两个可独立验收的单元，按顺序实施。来源接口、每页20条、限速、小时资格、零回复和尾部策略不变；不混入并发、按楼全面重构数据模型、页面功能或公网部署。

## 当前成本与选择

现有progress嵌入完整metadata，metadata又有独立存储副本。请求预算钩子调用get_progress/set_progress，导致少量计数变化也处理整个metadata；尾部候选控制和心跳读取还有重复工作。

后台save_result经过build_batch、freeze_batch、prepare_handoff，再materialize；这里包含完整按楼/按用户文件视图、目录复制和重复校验。已有文件导入路径提供了必要的校验与事务保护，不能直接绕开它们。

不采用降低持久化频率、关闭SQLite同步或跳过校验来提速。推荐分离热控制数据、共用规范化校验，再减少不必要的物理文件处理。

## 单元A：检查点格式与控制通道

在现有SQLite工作集内引入版本化布局，不新建外部服务：

| 数据 | 保存方式与访问规则 |
| --- | --- |
| metadata | 唯一权威副本，包含现有楼状态和刷新证据 |
| progress | 游标、扫描状态及恢复信息，不再嵌入metadata或重复请求计数 |
| request_control | 小型独立记录：已用请求、上限、检查点版本及当前请求诊断 |
| progress_summary | 同事务维护的评论/楼数量与阶段统计，供worker心跳读取 |
| comments/pages/tail候选表 | 保留原职责与原子合并规则 |

本轮不把所有楼状态拆成独立表；分页提交仍允许一次保存metadata。主要先消除每次请求扣费、候选控制和心跳中的重复大对象操作，为后续优化留出清晰接口。

### 新旧接口行为

- 请求预算改为专用读取/扣费接口，仅访问request_control；每次实际请求仍先持久化扣费，不能批量延迟记账。
- worker心跳读取轻量统计及必要控制字段，不为展示数量反序列化所有楼正文和证据。诊断/导出需要完整metadata时仍走完整快照接口。
- get_progress、read_checkpoint等完整读取保留兼容的返回结构，需要时重新组合metadata；是否曾附带metadata由内部标志保留，不能给旧调用者无条件添加新字段。兼容目标是原权威metadata、记录和控制语义，不是保留已过时嵌入副本的值。若旧save_metadata导致两个同身份副本不同，重组明确使用权威metadata行；需以此构造迁移断言，而不是要求过时副本字节相同。
- set_progress/commit_page等写入拆分字段，但保留最大已用预算、最小预算上限和原检查点版本规则。高频控制写入不替换调用者已持有的metadata引用。
- metadata、评论、页提交标记及对应统计在同一事务中更新。所有metadata写入入口都必须更新统计；摘要不可伪装成采集完成或发布依据。
- 尾部候选页不能进入已确认评论或统计；promote与回退决定保持原子性。控制通道不持久化调用者未验证的候选metadata。

### 版本、预算和摘要的精确定义

格式版本与checkpoint_revision分开。新增页成功提交、首次tail promote沿用现有revision递增规则；重复页、重复promote、请求扣费、save_metadata、候选控制和已确认abandon回退不递增该revision。迁移不因为改变布局推进逻辑revision，否则会使原恢复授权错误失效；候选尝试编号和原恢复证明约束同时保留。

worker的PostgreSQL请求计数及所有权检查仍保留，不能只剩本地计数。延续先守卫/持久扣费再发送请求的顺序；两处计数不能假装处于同一事务。崩溃恢复保守取已用请求的较大值、适用上限的较小值；已扣费但未发送的间隙不能自动退款。CLI无PostgreSQL时仍由本地控制记录执行预算。请求失败、候选回退和重启均不得重置额度。

progress_summary按当前heartbeat语义生成：comments为已确认comments表行数；threads为len(_threads)；verified_threads为reply_check_state等于complete的数量；unavailable_threads为unavailable为真值的数量；phase按finished优先import、其次main_done为replies、否则main。为兼容保留既有字段名，其中历史complete不能被宣称为本轮访问过详情；统计本身不是完成证明。

只改变progress的写入也要同事务更新派生phase，不能仅在metadata变化时更新。纯扣费只更新request_control，不要求重算所有楼统计。轻量读在一个SQLite读事务内绑定格式标记、必要控制和summary；完整读同样在一个快照内重组，不分多次无事务读取造成混合版本。

旧格式只读场景可走原兼容读取，首次持锁升级时重建summary。新格式summary缺失或损坏不能假报0或用它决定发布；由持锁写入者事务内重建。仅派生展示摘要不可用时，不应妨碍独立的正常租约续期；原安全控制字段不可用仍按原规则停止。心跳不得持续隐式解析大metadata来掩盖未维护的summary。

### 升级与回退

新格式使用独立格式标记，不能靠“有没有metadata字段”猜版本。原版本只读读取继续可用，不在只读操作中迁移；拥有工作集写锁的写入者可在单个SQLite事务中升级，成功后最后写格式标记，失败整体回滚。检查到未知更高格式时，在任何建表、补写或迁移之前拒绝写入；只读也不能把它猜成旧格式。覆盖CLI、worker、恢复/可用性处理及其他可变Checkpoint入口，不能只保护一个入口；必须确认旧写入进程已停止，SQLite事务锁不能代替阻止旧程序在升级后继续按旧布局写入。

迁移以原metadata行作为权威，与既有freeze/read_checkpoint语义一致；progress中的副本不是第二个可选择的来源。若两个副本视频身份不同或权威数据损坏，拒绝迁移；普通save_metadata造成的同身份内容差异不能被误当作新候选发布。缺失权威metadata但有嵌入副本时，不自动把副本晋升为已确认数据。

评论行、分页键、尾部候选与请求预算无损保留。停止旧worker并备份后升级；旧版本不支持新布局，不混跑。若需要回退，停写并使用保留的升级前工作集，说明恢复点之后的任务状态不可当作已备份；不覆盖原数据库结果或自动删除新工作集。

## 单元B：共用校验的数据集与直接入库

引入内部只读ValidatedDataset，表达固定批次的manifest、规范化评论、楼/用户索引、缺口信息和摘要。评论正文只持有一份；各视图引用评论ID，不为用户视图再复制整份正文。

共享校验层负责评论schema、身份归属、去重、计数、父关系/缺口、时间和各视图一致性；构建层只对采集输入推导分组和覆盖，不能把已验证文件强制重新构建。输入冻结后不能被调用方修改；通过私有复制及递归只读接口维持所有权，摘要必须绑定实际消费的数据。大样本内存与构建成本纳入验收，不以磁盘提速换取无界额外副本。

两条入口使用同一个已验证数据集：

1. 文件导入：保留路径、符号链接、指针切换、文件集合及一致性检查，将已验证的源逻辑文档装入ValidatedDataset；原manifest、楼/用户元数据、扩展字段、行序及JSON标量值保留，不通过build_batch重建或修正后再接受。非法输入仍拒绝，不能规范化成合法数据掩盖错误。
2. 后台采集：从一致工作集快照，经构建层生成原有逻辑文档，再执行同一内容校验，不生成按楼/用户目录，不调用copytree再读回。共享的是内容校验规则，不是强制将两个入口重新推导成另一份文档。

冻结边界同时覆盖嵌套manifest、索引、扩展元数据及handoff消费的尾部、零回复、周期和历史证明。外层frozen dataclass不足以保证内部dict/list不可变；不得返回内部可变引用，调用方修改原输入或返回视图必须被拒绝或仅改变独立副本。所有校验和物化使用同一私有快照，不能冻结评论后再从仍可变的原metadata读取证明。

文件导出仍由数据集的逻辑视图写出原有目录和JSON/JSONL，输出路径及协议不变。后台直接入库不等于自动生成D:/Data文件；用户需要文件时继续显式导出。

### 摘要与幂等

“同一固定逻辑批次”指相同schema_version、export_id、时间、路径映射、manifest/楼/用户文档、评论与unclassified行序、扩展字段及JSON标量表示，而不只是同一视频或同一组评论ID。此条件下，文件适配器和内存适配器必须产生相同的现有canonical digest，保证导入收据和重试幂等不因入口改变而冲突。逻辑视图仍包含原路径、空README和相同排序/JSON值；按现有相对POSIX路径字典序组成[relative_path, parsed_value]序列，JSONL为保持行序的数组，README值为空字符串，再使用现有ensure_ascii、sort_keys、separators和非有限数拒绝规则。不得自行将1.0转成1或丢弃已验证扩展。允许按序流式计算摘要，但必须证明编码与当前算法一致，不能依赖物理文件才能计算。

不另造未经版本化的摘要替换已有值。若实现中无法满足摘要等价，必须回到设计审阅，不能静默改变收据规则。

### 入库与证据安全

复用现有正文载荷去重、成员写入、回收和原子发布。仅将导入器的数据来源从目录读取适配为ValidatedDataset，不删除文件入口，也不新增绕过校验的SQL捷径。

prepare_handoff仍需校验任务、视频、基线版本、批次摘要、实际评论及尾部/零回复/周期证据；“是内部生成的”不能成为跳过校验的理由。materialize继续在同一事务内完成数据、指针、上下文和任务终态，失败整体回滚，旧结果保持可读。

候选数据冻结和通用校验在数据库写入事务前完成，提交时仍检查租约和取消。对于新的物化操作，基线版本必须匹配，不能覆盖并发的新结果。保留现有已成功收据重放例外：同一video/export_id/digest且完整refresh_context一致时，按现有收据生命周期、可见指针及上下文规则识别幂等重放，不仅因cache_version已改变就拒绝；其他情况仍拒绝冲突。重放不是任意重建已回收状态或重新发布旧结果的许可。后台任务不在入库提交前发布文件。

## 验收与测量

先在固定、虚构工作集上测量独立阶段：请求扣费、分页提交、尾部候选、心跳读取、数据集构建、物理文件处理和数据库提交。区分CPU、SQLite/文件I/O与来源等待，不把总耗时都归于数据库。

硬性行为指标：

- 高频请求扣费不读取/序列化/更新metadata；已用计数和预算上限仍持久化且单调。
- progress不再物理保存metadata副本；完整快照重组后语义与旧格式一致。
- 心跳只读取轻量统计；增加metadata体积不增加心跳解析的正文体积。
- 后台入库不生成或复制导出目录；文件CLI仍通过原安全校验。
- 相同固定批次文件入口与直接入口的摘要、数据库查询、再导出、覆盖和内部证明一致；保留源扩展和JSON数值表示。
- 构建后修改原始嵌套对象或尝试修改返回视图，不得影响摘要、验证结果和物化内容。
- 新基线冲突被拒绝；成功提交后的合法收据重放仍幂等，不重复发布或回收数据。

正反例覆盖：旧格式升级及中断回滚、未知格式写入拒绝、metadata副本差异、逻辑revision保持、双层请求扣费间隙及恢复、重复页、跨进程只读快照、进度单独变化的phase更新、摘要重建与展示失败、候选未确认、原子promote/回退、零证据历史反证、固定期限、尾部链、坏JSON/身份冲突、符号链接/路径越界、并发基线更新、guard异常和重复物化。

性能用多个规模及多轮固定数据对比，记录中位数与尾部耗时；时间阈值不放进易抖动的普通CI。先用结构性断言证明少读/少写/少文件操作，再以实测决定提速幅度，不预先承诺整个视频提速比例。
