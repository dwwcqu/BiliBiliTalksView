## 后续验证与实施门槛

- 入口：同一 Python 客户端验证剧集、视频和评论区标识的一致性。
- 客户端：显式应用 User-Agent；标准参数与 WBI 签名配置来自公开网页协议，配置变化需重新验证。

- 差异：真实两次观察与本地构造样例分别验证；新增观察、字段变化、未再次观察、无变化四种结果分开处理。
- 目标服务器尚未提供访问方式，服务器运行验收须独立完成；不因开发电脑成功宣称服务器已通过。
- 在全量末页/全楼与服务器门槛未满足前，保持验证阶段，不开始数据库、网页或模型功能。实际验证结果在对话汇报，不附入库报告或数据。

### 分页重叠的后续验证门槛

热门排序的跨页重复必须与游标循环分开处理：整页 ID 已观察过，不足以单独证明接口拒绝或分页循环；有结束标记前不能按重复页宣称完整。先前保守规则遇到整页重复即停止，断点保留为未完成。用户已确认继续验证重叠处理；仅允许显式恢复这类本地保护停止，不恢复接口拒绝。

下一子步骤先验证排序及重叠处理策略：明确有限连续重叠页预算，继续只消费服务端返回且未使用的游标；预算耗尽则标记无法确认覆盖。评估时间排序能否改善稳定性时必须建立独立检查点，禁止跨排序沿用游标。比较排序覆盖与终止证据后，再确定业务采集器的重复页判定规则。不得把调整本地重复页保护用于继续被接口拒绝的请求。


### 本轮执行规则：有限重叠续采

使用断点后少量真实页验证“重叠后仍有新 ID”的假设，并用本地记录检查判定规则。当前候选规则允许游标前进的孤立重叠页，连续 5 页无新 ID 则停止并标未完成；新 ID 出现后重置连续计数。游标重复、异常空页、访问拒绝仍立即停止。连续重叠计数与下一游标共同持久化，恢复不能清零预算。仅在上述小样本验证成立后，从原热门排序断点继续，沿用总计 4000 页的安全上限。

页面显示总数、接口报告总数、去重主楼数及逐楼实际回复数分列核对；总数变化或相等均不作为完整性证明。本轮仍以走通主楼末页为目标，不开展网页、产品数据库或模型实现。

## 当前阶段：逐楼回复分页与断点验证

用户已确认继续验证全部楼内回复，采集由可独立运行的 Python 脚本执行，不依赖 Agent 或桌面浏览器。沿用当前视频与已完成的时间排序主楼快照；实际服务器运行仍需目标环境另行验证。

### 设计与执行步骤

1. 小样本核对回复接口每页实际容量、连续页不重叠、尾页和尾后页。请求 `ps=20`，以响应 `page.size/num/count` 校验；不能假定更大请求值会提高返回容量。
2. 为主楼快照中报告有回复的每楼建立任务。零回复楼保留 `empty_at_main_observation` 状态及原观察时间，不称为本轮重新核验为空，也不保证观察之后没有新回复。
3. 每页原子保存回复、页序和下一页；每条回复保留字符串 ID、根楼、父评论、UID、昵称和内容。来源未返回的父节点标记为缺失，不伪造回复关系。
4. 串行、至少 2 秒间隔、20 秒请求超时；总请求预算 12000，每楼最多 1000 页，预算耗尽标未完成。访问拒绝立即停止整个运行，不自动重试；结构异常或无法解释的覆盖差异保留楼状态，明确未完成。
5. 用小楼与大楼核验候选结束条件：已到报告的最后页，页码和容量有效、累计去重数与报告数一致且本轮计数稳定。抽样尾后空页只作补充证据。计数变化、重复页或缺口须额外核验，不能仅凭短页或计数接近判完成。
6. 先验证暂停、恢复与事务回滚，再执行逐楼遍历。任务结束只说明指定主楼快照及对应采集区间的可见范围；分别汇报完成楼、待采楼、部分楼、主楼观察时为空的楼和实际取得回复数。
