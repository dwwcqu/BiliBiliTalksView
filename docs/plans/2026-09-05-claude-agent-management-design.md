## 已确认范围

- 后续网页后端通过服务器上安装的 Claude Code CLI 执行分析；客户端浏览器不直接运行 CLI。
- 输入采用 [CommentExport 2.0.0](../references/comment-export-protocol-v2.md)，兼容 [1.0.0](../references/comment-export-protocol-v1.md) 的 JSON／JSONL 导出；入口为 current.json。README.md 在上游原始导出时为空，进入分析阶段时已补充内容，作为视频背景及分析说明读取并固定版本，不因其非空拒绝分析。模型只读取分析侧完整校验后固定的输入，不依赖上游保留旧批次。
- 每个视频复用已有主 Agent 和子 Agent，不因再次分析就自动创建新成员。
- 协调规则维护于 [协调提示词](../../config/prompts/video-agent-coordination.md)，分析标准维护于 [八方向标准](2026-09-05-discussion-analysis-standard.md)。

## 采集交接前置条件

分析入口必须先满足[采集与分析交接契约](2026-09-05-collection-analysis-handoff-design.md)，由程序校验固定快照、覆盖策略和请求去重后才启动或恢复视频会话。Agent 不自行判断采集目录是否写完。

## 推荐接入方式与替代方案

推荐每视频一个可恢复主会话，加主会话内的自定义子 Agent。程序用明确主 session_id 恢复；主 Agent 按已有 agent_id 恢复子成员。实际恢复工具语法和边界依赖 CLI 版本，需验证后适配。

Agent Teams 暂不作为默认：官方列出进程内队友不能随 resume 恢复的限制，与长期复用目标不匹配。独立 CLI 会话组成工作池是备选，但需要程序承担成员之间的消息路由，并非原生子 Agent 的同一实现；只有默认方案验证失败后再讨论。

角色定义、会话历史、可选 memory、最终画像是不同对象。反复传入同名角色配置不等于恢复同一成员。会话恢复可以重新启动进程；不要求旧进程常驻。memory 可辅助记忆，但不能代替 transcript 或画像证据，首期不依赖跨视频共享 memory。

### 2.1.261 新增接入注意事项

- `claude agents --json --all --cwd <path>`：可包含已完成的后台会话；不是完整子 Agent 历史列表。顶层帮助确认 attach、logs、stop、respawn 等入口，stop 保留历史；不能通过测试 stop／respawn 影响其他任务。
- `--bg --resume`：帮助明确指出，目标已运行时可能建立副本。必须先获取视频单写锁并核对状态、实际返回 ID；不允许用后台 resume 绕过“不得额外创建”约束。自动任务仍优先采用受管理进程的 `-p --resume`，`--bg` 与 `-p` 不混用。
- `--system-prompt-snapshot on|off`：帮助说明 on 可复用保存的系统提示，后续不同提示可能被忽略至压缩；自定义追加／替换提示默认关闭记录。为支持每轮明确规则更新，启动方案应显式考虑 off，并继续由本程序冻结本轮文件；该参数在系统提示记录尚未启用的环境不生效。子成员不能仅依赖主提示参数更新，仍需显式传递本轮版本并验证。
- `--forward-subagent-text`：新版帮助列出，可在 `-p --output-format stream-json --verbose` 下获取更完整的子成员消息。事件与内部内容仅作受控运行数据，不直接暴露为网页公开输出，也不假定已有完整审计。
- `--permission-prompts none`：新版帮助列出；无人回答的权限请求自动拒绝，适合后端明确失败处理，不等于授予权限。
- `--restricted`：新版帮助列出，可限制文件工具范围及部分命令工具，并影响设置来源。可作为后端隔离候选，仍要验证所需读取器和子成员工具可用性，不能单靠提示词约束。
- `--append-subagent-system-prompt`、`--max-turns` 及系统提示文件参数仍按官网支持记录；顶层帮助未列出不代表不支持，也不以带 `--help` 成功退出冒充这些参数实际生效。
- 并发控制必须由运行程序覆盖新建与恢复两种路径；官网内置的子成员新建限制不能代替复用任务的并发管理。

CLI 参数示意，不是可直接用于生产的完整命令：

```text
首次：claude -p --session-id <new-main-uuid> --output-format json <初始化任务>
后续：claude -p --resume <saved-main-session-id> --output-format json <本轮任务>
```

启动程序须额外显式装配角色、规则、背景、权限、预算和读写接口，并从真实输出确认 ID。提示词文件每次重新加载；默认先考虑追加方式保留 CLI 工具指导，不让程序拼接不可信 shell 命令。

## 会话保存与复用契约

程序需要保存下列逻辑信息，具体存储格式后定：

- 稳定视频标识、绝对工作目录、运行宿主／服务账号与 CLI 版本。
- 主 session_id、逻辑成员标识、实际子 agent_id、角色和所属主会话。
- 输入快照、规则／背景／协调版本、任务范围、检查点和结果位置。
- 运行、空闲、部分完成、失败、不可恢复等实际状态；同视频主会话加单写锁。

主历史与子 transcript 在 Claude 的本地状态目录；只保存 ID 或角色文件不足以恢复。官网默认有 30 天清理期限；需要明确 retention 配置，并在清理期限外保有独立可恢复备份。不能把有限天数设置等同于永久保存，也不使用 `cleanupPeriodDays: 0` 作为永久保存技巧。当前不修改机器设置。

服务器用稳定工作目录、稳定服务账号和持久化存储保留会话状态。备份范围包含该任务恢复所需的主／子 transcript 及引用的工具输出，认证材料单独管理，不交给分析 Agent。最终画像、证据和任务记录独立持久保存，不只依赖 CLI 历史。实际运行数据不得提交 Git。

重启同一服务器后优先恢复原主会话，再恢复原成员。迁移机器、改变路径或升级 CLI 的恢复兼容性必须实测；设计仍使用稳定工作目录，避免路径迁移影响输入定位。恢复丢失／不支持时报告具体阻塞，不静默新建替代者。只有经确认的替代流程才能建立新旧映射。

长期复用不会消除历史上下文成本，也不保证全部旧文本一直保留在活跃上下文；恢复后重新读取本轮规则和必要原文。旧画像按快照和版本判断有效性，不能直接沿用成新结论。

## 子 Agent 的规则传递

主提示词不应假定自动完整传入子 Agent。每次分配／恢复明确传递冻结的通用分析规则、视频背景、任务范围及必要协调要求。首次角色配置可从本地模板装配；新版提供的批量追加子提示参数须通过版本检查再采用。

修改协调文件作用于下一轮，不混用同一运行内的规则。恢复旧成员时发送显式更新并要求确认当前版本。规则涉及权限或角色系统提示变化时，先验证恢复语义，不能声称改文件自动改写旧会话。

## 技术验证计划与验收门槛

1. 使用无真实用户数据的临时视频目录，提供脱敏或合成材料；验证账号、模型及预算配置后才发起模型调用。
2. 首次建立主会话并创建两个自定义子成员，保存 CLI 返回的真实 ID 与成员归属；不把本提示模板当作已建立成员。
3. 完成一轮后退出进程，从同一目录恢复主会话，再让原两个子成员处理新批次；核对主 ID、子 ID、工具记录及实际返回，确认没有新建替代实例。
4. 验证协调文件更新后原成员采用新版本，同时不会把旧快照的评论混入新结果。
5. 验证进程重启、部分失败、重复请求与锁；核对任务不重复、最终结果单写、有效证据去重。
6. 验证历史文件丢失时明确失败，以及备份恢复后可继续。运行文件只放忽略目录；不创建或提交调查日志。
7. 在目标服务器复验所选版本和目录布局，确认可恢复状态持久化及权限范围，再设计网页后端接入。

输入及画像存储目录已在[存储设计](2026-09-06-analysis-storage-design.md)确认。尚待确定：模型与预算、正式成员数量与并发、保留配置／备份实现，以及缺失会话的替代授权流程。本次不实现这些未决部分。

## 调用前置条件与失败策略

当前配置已通过实际调用。合成样例验证支持在主会话进程退出后恢复同一主 ID 和两个原子成员 ID，并保留历史记忆；主／子 transcript 已落盘。新规则执行仍未整体验收：一个成员通过新规则和新快照检查，另一个沿用旧任务范围，明确重新分配后的补充调用超时。运行程序必须分别检查身份恢复、规则采用和任务产物，不以 CLI success 或 completed 状态替代业务验收。

- 401 认证失败不做长时间自动重试，不新建成员或切换账号掩盖失败；暂停并提示修复服务配置。
- 此次成功调用使用用户当前配置的 deepseek-v4-pro；CLI 提示 unrecognized_model，结果仅适用于本次 CLI／服务／模型组合，不能外推为 Claude 模型或其他兼容服务的保证；不擅自替换用户选择。
- 启动器需明确环境变量与本地配置的优先级。排查只记录主机和键名／存在性，不输出令牌；进程继承配置不能静默覆盖预期服务。
- 无结果事件时不得将费用视为已确认零成本；本地调用记录无法替代服务端账单。
- 后续继续原测试主会话和成员，优先解决规则切换及超时处理；不重新创建成员绕过失败。临时材料、ID 映射及运行证据仅保存在忽略目录中。

## 由复用验证确定的接口约束

- 恢复结果核对 SendMessage 返回的 resumedAgentId 与登记 ID；新建与恢复分别计数，不能按角色名称判断复用。
- 每次重新分配明确声明旧批次任务结束，给出新任务标识、快照、规则版本与输入对象。成员的持久职责应允许协调者更换批次；批次范围不应表述为永久角色权限。
- 任务通知 completed 只表示成员停止执行。输出中的 snapshot、rule_version、comment_id、证据原文及覆盖范围须逐项校验；拒绝任务或返回旧快照归为未完成。
- 流式输出可能包含多个 result 事件以及后续任务通知，不能读取第一个 result 就停止等待；以所需成员产物全部通过校验并且进程正常结束为一轮完成条件。
- 重试仍保持原成员身份，并设明确超时；超时保留中间结果与检查点，不把未返回费用的调用算作零成本。兼容模型返回的费用元数据未必对应服务商实际账单。
- 本次只验证合成样例的恢复机制，不证明八方向分析质量、长期保留、迁移机器或服务器重启恢复已经完成验收。

## 主线更新后的协调边界

主线已有采集 HTTP API、PostgreSQL 和持久队列，分析阶段不再承担采集总控或另造采集队列。后续自动分析必须由程序将明确的 result_state_id 导出、冻结并完成准备，才恢复主 Agent；采集 worker 的临时文件不是长期输入。详细映射见交接契约第 11 节。

角色配置每轮必须校验实际输入协议、export_id、prepared_run_id、完整分析 run_id 和 context 版本。角色名称、UID、export_id、state_id、session_id、agent_id 分属不同命名空间，不互换。主 Agent 可以调度，但输入完整性、版本校验和任务发布必须由程序执行。

模型执行阶段的进入条件：输出画像 Schema、执行配置／费用账本、成员规则切换验收、失败恢复策略明确后再开发。当前试验仅证明指定环境中原成员 ID 与部分记忆可恢复；一个成员未可靠切换规则，不能据此自动批量处理所有真实评论。模型路由或角色权限变更时先验证恢复兼容性，不静默创建替代成员。

提示词中的并发、费用和读取范围约束不是硬限制；运行程序需对新建与恢复都执行限额、持久化累计费用和身份校验。来源文件和导出 JSON 均视为数据，只有本轮由调用方指定并固定的规则文件作为任务规则；本地 README 背景不自动成为修改八方向规则或工具权限的授权。

## CLI 适配层接入子阶段

2026-09-06 新增 analysis_execution 本地库，范围见 [适配层计划](2026-09-06-claude-cli-adapter-plan.md)。命令装配、显式首次/恢复主会话、有限捕获与超时、会话锁、不可重复 attempt 记录、完整事件解析属于传输层。原执行门槛仍适用：它不提供子成员规则采用证明，不签发 ExecutionContext，不自动接入 accept_response，不代表真实视频分析已贯通。

本层 bare 模式以可预测的显式配置为前提，不读取 OAuth；不能无提示用它替换历史订阅登录方案。下一子阶段必须确定实际认证/服务配置、成员启动及恢复工具事件适配，提供冻结输入读取证明和逐成员规则验证，连接单次/累计预算及合成端到端测试，再进行小规模真实模型验收。Read/Agent/SendMessage 允许列表不等于目录沙箱；部署身份与权限须另行落实。

官方依据：[programmatic CLI](https://code.claude.com/docs/en/headless) 和 [CLI reference](https://code.claude.com/docs/en/cli-reference)。当前仅只读核验指定本地 CLI 的 version/help，没有新增模型调用。

## 已登记成员投递闭环（2026-09-07）

按 [投递计划](2026-09-07-agent-dispatch-plan.md) 已连接固定评论/规则/标签/Schema 投递、原生 SendMessage 恢复与完成通知关联、持久化证明、响应接受与用户汇总后的画像保存。采用一次主调用只恢复一个登记成员的保守接口，尚不自动创建成员或批量循环。合成三阶段闭环已用于验证；真实模型及正式初始登记另行验收。

准备状态 ready 和固定 allow_partial 策略是执行前置条件；offline_prepared 或外部 authorized=True 都不能取代它们。每次投递有独立 attempt 和正文摘要，标签目录另存摘要固定在 execution.json，不能只修改运行时标签而继续声称同一规则配置。CLI返回成功后仍需本轮投递/原生结果/证据的逐层校验。

原生证明记录被接受回执绑定并在画像重读时检查。CLI完成后验收中断可从同attempt匹配记录继续，不重新发起模型。调用记录、证明和结果文件都不是公共静态资源。规则摘要是版本确认，不能保证模型推理遵守规则；画像质量仍需真实样例评估。

当前 actual reported model 的证据范围仅为主会话 init，执行文件明确 reported_model_scope=main_session_only、member_models_verified=false，画像保留相应限制。恢复成员的转发父工具 ID 可能沿用首次创建，尚不能仅据此独立归属其实际模型，不能把主模型外推成所有子模型。

## 初始化真实验证后的边界（2026-09-08）

原生初始化、空主会话安全恢复、原ID握手修复、费用和诊断接口已实现。管理模式必须显式非bare；CLI2.1.261实测bare只开放Read而缺少所需代理工具。创建和加载定义分离，恢复不开启创建工具。握手格式要求必须直接传给子成员；主协调者最多一次同ID格式纠正可被记录，不能将纠正误认为新增成员。

已完成原生创建/握手的身份可在主CLI预算终止后保留，但预算终止仍被记录，不冒充整个进程成功，不影响分析结果的严格接受门槛。未知费用、不完整原生事件、未结束任务或CLI拒绝恢复均阻塞。只读初始化状态不能作为完整团队登记。

真实验证发现预算停止会触发CLI拒绝自动恢复的取消状态。当前原生方案尚未完成整组真实验收，不能宣称长期无人值守复用已达成；不允许为了通过测试静默创建替代者。下一步必须选择 [中断复用策略](2026-09-08-agent-resume-strategy-proposal.md)。普通会话池是原设计的备选，仍需用户确认和独立验证；本轮未迁移或替换任何成员。

### 已确认的会话池执行方向（2026-09-08）

用户已选择独立普通 CLI 会话池：主/工作会话分别保存 UUID，由程序管理关系，原生取消记录保留。设计与接口见 [会话池计划](2026-09-08-session-pool-plan.md)。普通工作会话直接接收完整冻结任务包，采用独立证明适配器复用输出验收和 UID 文件保存，避免原生子成员取消后无法恢复的路径。角色文件变化通过新分析批次传入，沿用原 UUID；pool 初次角色摘要不作为后续任务的当前角色摘要。自动批量协调仍是后续阶段。
