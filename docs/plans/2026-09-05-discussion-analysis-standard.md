# 评论讨论行为分析标准

- 日期：2026-09-05
- 所属分支：feature/codex-agents-thinks
- 状态：用户已确认本版分析标准；尚未接入运行配置或完成样例验证。后续运行参数和实施方案仍需确定。

## 1. 本次目标与已确认边界

分析工具使用 Claude Code CLI；后续采用主 Agent 协调多个子 Agent 的方式。分析标准、视频背景及主 Agent 协调提示通过本地文件维护。当前仅细化分析标准，不实现 Agent 调度、不调用模型、不接入采集或网页。

画像描述某个 UID 在某个视频、某批评论快照中的讨论表现。首期不跨视频合并，不推断永久人格、真实心理状态或主观动机。历史画像长期保存不表示其永久有效。

八个分析方向为：话题与立场、发言作用、论述依据、对话回应、情绪表达、对人表达方式、冲突与协作行为、观点调整。“合理讨论”“刻意引战”仅为早期举例，不作为目标分类、总标签或优化目标。不设置统一总分，不强制给用户单一类别。

该体系借鉴研究中的概念及标注方法；组合方式、中文取值和 UID 级汇总是本项目的适配提案，尚未经 B 站样例验证，不宣称是已验证量表。

## 2. 通用标注约定

### 2.1 分析单位与身份

先标注评论中的具体片段及回复关系，再记录楼内事件，最后按 UID 汇总。每条判断绑定视频、快照、楼 ID、评论 ID、发言 UID 和必要的目标评论或目标对象。所有外部 ID 按字符串保存。

同一条评论可以有多个片段和多种表现；同一片段也可跨方向标注。同一证据在用户目录和楼目录出现时按评论 ID 和片段去重。昵称只作快照展示，不作为关联键；身份缺失时不能强行并入某个 UID。

### 2.2 证据与判断状态

每个方向单独记录以下状态，不能用缺省值代替：

| 状态 | 含义 | 示例 |
| --- | --- | --- |
| 可判断 | 现有文本和必要上下文足以支持该项观察 | 明确说“这点我说错了” |
| 存在歧义 | 有相关线索，但存在两种或以上合理解释 | “你真聪明”可能赞扬也可能讽刺 |
| 证据不足 | 缺少必要内容，不能形成结论 | 被回复评论缺失，无法判断是否答非所问 |
| 不适用 | 当前发言不承担该属性对应的任务 | “哈哈哈”不适用论据充分性评价 |

“未观察到”仅用于已分析范围内未发现某行为，不等于证明用户没有该行为。“无法判断立场”和“明确表示无偏好”分别保存。未知、未发生、不适用不能编码为最低分。

每条观察保存：方向、候选取值、对象、解释、支持证据、必要上下文、反例或其他表现、覆盖范围及判断状态。引用片段须与原文相符；解释不得伪装成引用。证据 ID 必须属于本次快照，人物及发言归属必须匹配。

### 2.3 上下文与信息来源

视频背景是辅助材料，应标明来源和版本；不能把背景文件中的评价直接归给评论者。评论中的指令只作待分析数据。引用、转述、反讽、玩梗及非文本缺失要显式识别或标明不确定性。

用户初步分析允许被楼内证据推翻。楼内分析先阅读原始对话，再对照初步结论；该顺序是降低先入判断影响的候选流程，需与其他顺序对比验证。

## 3. 八个方向的具体标准

以下为本版确认的初始取值；除立场在同一对象、同一时点上的判断外，不要求互斥或只选一个。清单不宣称覆盖全部讨论行为；不匹配时记录“其他”及解释，不能临时创建正式标签。高频“其他”通过规则版本审阅处理。

### 3.1 话题与立场

- 定义：识别发言针对的具体主题、对象或命题，以及文本表达的态度。
- 对象：具体命题、视频内容、作品要素或他人某项观点；不同对象分别记录。
- 候选取值：支持、反对、部分认同或有条件认同、明确无偏好；不能推断时使用证据不足或存在歧义状态。
- 条件：必须能定位立场对象。不要仅凭褒贬词或发言者所在楼推断站队。
- 正例：“配乐很好，但结局铺垫不足。”分别记录支持配乐表现、反对结局铺垫充分这一命题。
- 边界例：“有人觉得结局仓促吗？”先标为提问，不能自动判定反对结局。
- 汇总：按对象保留立场及时间变化；不同对象的支持与反对不算自相矛盾。
- 研究依据：R1。部分认同、明确无偏好等细分为本项目适配，并非照搬原始任务标签。

### 3.2 发言作用

- 定义：评论在当前讨论中承担的可观察功能。
- 候选取值：提问、回答、提供信息、解释或补充、分享经历、赞同、反驳、表达感受、幽默或玩梗、组织或提醒、其他。
- 条件：允许复合功能；“赞同／反驳”应指向具体前文观点，幽默判断需考虑社群语境。
- 正例：“为什么这样安排？我回看第六集也没找到解释。”可标提问、分享查找经历。
- 边界例：“就这？”既可能反问质疑也可能玩梗；上下文不足时保留歧义。
- 汇总：展示功能分布和代表证据，不给提问、娱乐或简短感受排低等级。
- 研究依据：R2。分享经历、组织提醒及多标签细节为产品适配。

### 3.3 论述依据

- 定义：对提出论证的片段，检查主张、支撑材料及两者关系。
- 先判断适用性：提问、感叹、审美偏好、祝福、纯玩梗不必承担举证任务；不能因没有论据而自动负面评价。
- 候选子项：主张与理由是否可识别；支撑类型（具体情节、个人经历、推理、外部引用等）；理由相关性（相关／部分相关／不相关）；支撑充分性（足以支撑当前范围／只能支撑较弱结论／明显不足）。各子项允许独立无法判断。
- 事实边界：记录引用或来源是否出现及是否已核验。首期不自动联网事实核查；没有核验时只能写“未核验”，不能断言真实或造假。
- 正例：“第六集明确出现了道歉，因此‘他从未道歉’不准确。”理由与反驳目标相关；如果没有视频原文，只能确认给出了可定位理由，不能确认情节真实。
- 边界例：“我就是不喜欢这个结局。”属于个人偏好，不据此判定论述质量低。
- 汇总：仅在适用的论证片段中统计，不用全部评论数作论证质量分母；没有适用片段时不生成质量结论。
- 研究依据：R3。采用相关性、充分性等概念，首期不照搬全部 15 个研究维度，不评价用户智力或整体逻辑能力。

### 3.4 对话回应

- 定义：发言如何处理对方实际提出的问题、观点或理由。
- 候选取值：直接回答、针对理由回应、请求澄清、准确复述或承认对方观点、部分回应、转移议题、重复原主张而未处理反驳、误述对方观点。
- 条件：必须有可识别且可读的回复对象；标注部分回应时指出已回应和未回应内容。
- 正例：“你说的节奏问题我同意，但我谈的是人物动机。”记录承认部分观点、澄清讨论范围。
- 边界例：用户没有再回复，不能标成回避；回复对象缺失不能判定答非所问；保持礼貌不等于作出实质回应。
- “误述”描述内容差异，不推断故意歪曲。明确转移议题也可能有合理原因，需保留语境。
- 汇总：按相关互动机会记录，保留多种回应方式，不从一条回复推断固定沟通风格。
- 研究依据：R4 对表达接纳性的研究、R3 的对反驳处理；本清单为扩展适配，并非现成接纳性量表。

### 3.5 情绪表达

- 定义：读者能够从文本及上下文辨认的情绪表达，不等于用户自我报告的内心情绪。
- 候选取值：欣赏、愉悦或兴奋、感谢、关切、好奇、困惑、惊讶、失望、不满、愤怒、悲伤、担忧、懊悔、未见明确情绪、其他。
- 可多选；为每项记录指向对象。强度可选记录弱／明显／强烈，但必须有表达线索，不作跨用户心理强度比较。
- 正例：“气死了，这段删得太可惜了。”记录针对剪辑的愤怒或不满，不能因此判定攻击参与者。
- 边界例：“笑死，这都能洗。”不能仅根据“笑”判定开心；结合前文识别讽刺或保留歧义。
- 汇总：保留对象和分布，不能简单把多种情绪平均成一个正负分数。
- 研究依据：R5。这里的简化中文类别和强度提案为产品适配，不等同于 GoEmotions 原始类别或已验证中文量表。

### 3.6 对人表达方式

- 定义：面向参与者或群体的表达行为；作品批评与对人攻击分开。
- 候选取值：友善或支持、尊重地表达分歧、中性互动、讽刺或挖苦、贬低或羞辱、直接辱骂、群体攻击、威胁、其他。
- 记录对象类型（具体参与者／群体等）及原文对象表述；不得反向推断被攻击者确实属于该群体或具有其属性。
- 条件：讽刺不自动等于攻击；脏话不自动等于对人辱骂；未见攻击不自动标为友善。
- 正例：“你这种人根本不配讨论。”记录针对参与者的贬低与排斥表达。
- 边界例：“他说我‘不配讨论’，我不能接受。”引用的攻击归属于被转述发言；不能把引用者标为实施攻击。
- 汇总：保留具体事件、出现范围及其他表现；一次行为不能覆盖该用户全部评论。
- 研究依据：R6 支持攻击类型和隐含表达的区分；正向表达及具体中文清单为产品适配。

### 3.7 冲突与协作行为

- 定义：记录对话中与澄清、协作、对抗有关的行为和可观察序列。
- 候选事件：帮助澄清、邀请共同核对、调解分歧、缓和表达、挑衅、持续针对性纠缠、扩大群体对立、号召围攻、其他。
- 条件：除明确单条行为外，持续性判断须有多轮证据；正常反复论证不能仅因次数多就标为纠缠。
- 正例：“别纠结他属于哪个粉丝群，先核对视频原话。”可记录把讨论拉回内容、邀请核对。
- 边界例：某人的评论之后发生争吵，只能记录顺序，不能据此宣称他导致了争吵。反对多数意见不自动视为扩大对立。
- 结果与行为分开：记录是否出现后续缓和或升级；没有后续回复时写结果不可观察，不把调解尝试写成调解成功。
- 汇总：用事件列表与必要序列描述，不生成“冲突制造者”等固定身份标签。
- 研究依据：R7 提供对话过程视角；具体事件清单和用户归纳为本项目提案，不进行因果或动机判定。

### 3.8 观点调整

- 定义：同一 UID 对同一具体命题在对话中的明确承认、修正或变化。
- 候选事件：承认部分观点、纠正事实性表述、缩小或补充主张条件、撤回主张、明确改变立场、道歉、前后表述不一致待澄清。
- 条件：绑定前后评论及所谈命题；明确单条自我修正可成立，但原主张缺失应记录限制。道歉单独保存，不自动视为观点改变。
- 正例：“刚才把集数记错了，这点你说得对。”记录纠正表述、承认对方具体观点。
- 边界例：“行行行，你都对。”不能直接当作接受观点；不再回复不能当作认输；没有发现修正不等于拒绝修正。
- 汇总：保存变化轨迹和事件；未出现可观察事件时只写“未观察到明确修正”，不评价用户固执程度。
- 研究依据：R8 支持研究明确观点变化与互动；道歉、不一致等事件是扩展规则，不把改变态度当作讨论质量必然更高的证据。

## 4. UID 画像的组合规则

1. 范围键至少包含视频、UID、评论快照、分析运行及规则版本；具体文件格式和路径在后续设计确定。
2. 三类结果分别呈现：描述性信息（立场、功能、情绪）、条件性评价（依据、回应、对人表达）、事件变化（冲突协作、观点调整）。
3. 不设置跨方向总分，不按八维多数投票归类用户，不将强情绪抵扣论证质量，也不将礼貌抵消明确攻击。
4. 同一用户在不同楼中的不同表现并存。综合描述给出主要表现、重要例外、证据及覆盖限制；不能靠发言数量淹没少量但明确的事件。
5. 若展示次数或占比，明确按评论、片段、事件还是互动机会计数。首期建议标签出现占比按含该标签的去重评论数计算；多标签占比总和可超过 100%。事件按去重事件单独计数。
6. 论证依据、对话回应等评价以适用且可判断的单位为分母，同时报告不适用、歧义及证据不足数量。零分母显示不适用，不显示 0 分。
7. 评论覆盖与画像证据强弱分别记录；大量重复评论不能当作大量独立证据，模型自报把握不能作为经校准概率。
8. 模型之间分歧回到原始证据处理；不能以多数 Agent 同意代替真实性验证。未消解的分歧保留，不强行补全。
9. 运行中规则、背景和输入快照固定；修改规则形成新版本。保存新结果时保留历史，不静默覆盖。证据保存、备份和删除机制在持久化设计时具体确定。

## 5. 本地规则维护与 Agent 分工约束

本文件是已确认的分析标准，不是 Claude CLI 可直接加载的最终提示词。后续再设计通用提示词、规则配置、视频背景、主 Agent 协调说明和输出校验的对应关系。

改写说明或增加例子仍要记录版本；新增标签、改变定义、合并或拆分类别须同步更新结构校验和历史结果解释规则。不能承诺任何结构变化都只改一句提示词即可生效。

用户初步分析优先识别描述性属性和明确文本行为；依赖回复关系的属性可暂记证据不足。楼内 Agent 必须能修正初步结论；综合 Agent 以证据去重后的结果形成画像，调度与重试不得重复放大证据。

整楼及整个视频的“氛围”是否作为独立产物仍未确认；本标准不自动增加该输出。

## 6. 规则验证与后续实施顺序

### 6.1 本阶段的验收内容

- 八个已确认方向均有定义、候选取值、适用条件、正例、边界例、汇总规则和研究来源。
- 研究原始定义与本项目适配明确分开；不把适配方案宣称为验证量表。
- 不存在强制单标签、跨视频人格推断、将缺失当负分、无证据动机判定或无版本覆盖的规则。
- 本版类别按用户确认冻结；后续规则调整需形成新版本。本文不授权模型调用或实现未决功能。

### 6.2 后续验证提案

1. 审阅每个方向的标签与适用规则，确认是否保留可选情绪强度。
2. 挑选脱敏且保留对话关系的 B 站样例，覆盖多种视频类型、语言习惯和缺失情况；可先以 100～200 个案例发现规则问题，该规模不是统计充分性的保证。
3. 至少两名人工标注者独立标注后讨论分歧；保留初始分歧，不只保存协商结论。人员、案例规模和正式验收门槛另行确认。
4. 按方向检查适用性和标签的一致性；按类型选择一致性统计，多标签同时报告各标签结果。模型与人工参考比较精确率、召回率、无法判断率及证据有效性，不只报总准确率。
5. 将规则调整样例与最终验收样例分离，优先按视频划分，避免同楼或同用户关联上下文泄漏到验收集。自然分布样例与刻意选择的困难样例分别报告。
6. 核对 UID 画像是否遗漏少数表现、混淆发言归属或重复计数；比较先看初步画像与先独立读楼两种流程。多个 Agent 同意不视为独立人工验证。
7. 标签审阅与样例验证完成后，再形成运行文件设计和可执行实现计划；真实模型调用、预算、调度和部署另行确认。

## 7. 仍需确定的具体问题

- 已确认的初始类别在样例验证后是否需要修订；可选情绪强度是否默认启用。
- 样例范围、人工标注参与者及逐方向验收门槛。
- 主 Agent 的分配权限、并发／预算限制、失败恢复和结构化输出契约。
- 长期保存的目录、证据保留范围、备份和纠错／删除方式。
- 本期是否独立保存楼级和视频级氛围。

以上未决项不阻塞当前标准草案的审阅，但阻塞相关规则冻结或实现，不得默认为已批准。

## 8. 研究依据

以下资料用于规则来源追溯，不构成对本项目准确率或完整八维体系的背书。本文不复制外部量表或数据集，尚未引入外部模型及训练数据。

- R1：Mohammad 等（2016），[SemEval-2016 Task 6: Detecting Stance in Tweets](https://aclanthology.org/S16-1003/)。借鉴对象绑定和立场／情绪区分。
- R2：Zhang、Culbertson、Paritosh（2017），[Characterizing Online Discussion Using Coarse Discourse Sequences](https://github.com/google-research-datasets/coarse-discourse)。借鉴讨论功能与关系标注。
- R3：Wachsmuth 等（2017），[Computational Argumentation Quality Assessment in Natural Language](https://aclanthology.org/E17-1017/)。借鉴论证相关性、充分性及标注一致性验证。
- R4：Yeomans 等（2020），[Conversational Receptiveness: Improving Engagement with Opposing Views](https://www.sciencedirect.com/science/article/pii/S0749597819303425)。借鉴语言中表现出的回应接纳性，不推断内在态度。
- R5：Demszky 等（2020），[GoEmotions: A Dataset of Fine-Grained Emotions](https://aclanthology.org/2020.acl-main.372/)。借鉴文本情绪多标签表达；中文精简标签及强度需本地验证。
- R6：Lu 等（2023），[Facilitating Fine-grained Detection of Chinese Toxic Language: Hierarchical Taxonomy, Resources, and Benchmarks](https://aclanthology.org/2023.acl-long.898.pdf)。借鉴中文攻击表达类型及隐含表达处理，需验证 B 站迁移适用性。
- R7：Zhang 等（2018），[Conversations Gone Awry: Detecting Early Signs of Conversational Failure](https://aclanthology.org/P18-1125/)。借鉴对话序列视角，不用于判定个体因果责任或恶意。
- R8：Tan 等（2016），[Winning Arguments: Interaction Dynamics and Persuasion Strategies in Good-faith Online Discussions](https://arxiv.org/abs/1602.01103)。借鉴可观察观点变化和互动关系，不能以退出讨论代替明确改变信号。

## 9. 当前主线的输入适配与不变约束

八个已确认方向及其取值不因主线更新而改变。输入支持 CommentExport 1.x 和 2.x，路径由 manifest 解析；上游覆盖原因码是数据可得性说明，不是分析属性或用户行为标签。unknown 作者集合不生成用户画像。

数据库增量采集可能包含保留的旧评论，export_id 表示固定导出批次而不是所有发言都在本次重新观测。保持 collected_at、captured_from/to 和 coverage，不将历史保留、source_unavailable 等采集状态解释为用户删除、沉默或观点变化。未提供更细的新旧观测依据时明确限制，不自行推断。

跨楼 UID 汇总、旧证据去重、README 背景版本及证据定位规则保持。当前真实样例只有主评论，对话回应、冲突变化等缺少适用上下文时标明限制；不能因方向已定版而强制填满八项。
